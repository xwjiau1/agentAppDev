# Qwen投顾助手与Langfuse追踪

通过 Qwen-Agent 工具和界面提供投顾对话，并对查询与输出增加 Langfuse 追踪。

- 案例类型：完整应用（含门票助手界面参考）
- 来源：第12章 `CASE-langfuse使用/`
- 技术栈：Python、Qwen-Agent、DashScope、Langfuse；门票参考另用 SQLAlchemy、pandas、NumPy、Matplotlib
- 能力标签：工具注册、提示词规划、GUI、对话历史、输入输出追踪
- 代码入口：[基础投顾](1-hybrid_wealth_advisor_qwen_agent.py)、[追踪版](1-hybrid_wealth_advisor_qwen_agent_langfuse.py)
- 运行情况：未运行；原配置和依赖存在待核验项。

## 代码怎么看

1. 基础版 `QueryShanghaiIndexTool`（65–89行）注册模拟行情工具；`get_system_prompt`（93–171行）用客户画像描述两种处理方式。
2. 基础版 `init_wealth_advisor_agent`（175–195行）将模型、提示词和工具交给 `Assistant`，`app_gui`（252–284行）用 `WebUI` 启动。
3. 追踪版 `TracedAssistant.run`（243–403行）提取查询，使用 `observe` 记录输入、输出与元数据，再 flush。
4. 追踪版 `run_wealth_advisor`（482–543行）另提供函数调用路径；GUI追踪与函数路径应分别阅读。
5. [assistant_ticket_bot-3.py](assistant_ticket_bot-3.py) 是课上迁移 GUI/TUI 的门票助手参考，包含 SQL 执行和图表生成，并未调用 Langfuse。保留在原组内，不标作投顾功能。

## 使用条件

本轮只做静态阅读，未安装依赖、未调用模型或评估平台。原始 requirements.txt 原样保留，不能据此认定环境已可运行。以下命令按源码入口整理，均待运行确认；先进入本案例目录，再执行命令，避免相对文件加载失败。

- 基础版：`python 1-hybrid_wealth_advisor_qwen_agent.py`；按菜单选择 GUI/TUI，需 `DASHSCOPE_API_KEY`。
- 追踪版：`python 1-hybrid_wealth_advisor_qwen_agent_langfuse.py`；另设 `LANGFUSE_SECRET_KEY`、`LANGFUSE_PUBLIC_KEY`、`LANGFUSE_BASE_URL`。
- `requirements.txt` 含异常项 `~wen_agent==0.0.19`，原样保留；不能直接视作可安装依赖清单。
- 门票参考需要 MySQL 的 `tkt_orders` 表及 `mysqlconnector` 驱动，当前组未提供数据库数据和建库资源文件；建表字段仅在提示词中出现，不会自动建表。`resource` 路径常量存在，但当前代码未见实际读取。
- 仓库副本将门票参考111行连接串的账号、密码和主机改为 `YOUR_USER` / `YOUR_PASSWORD` / `YOUR_HOST`，运行前需自行配置。原课程文件未改动，业务逻辑未改动。
