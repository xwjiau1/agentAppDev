# 投顾AI助手效果评估

对简单查询和复杂投资分析采用不同流程，并用规则与 DeepEval 评估输出。

- 案例类型：完整应用（教学模拟数据）
- 技术栈：Python、LangGraph、LangChain Community Tongyi、Pydantic、LangSmith、DeepEval
- 能力标签：条件路由、状态传递、结构化输出、规则评估、LLM评估、调用追踪
- 代码入口：[主程序](1-hybrid_wealth_advisor_langgraph_langsmith.py)、[评估启动示例](3-run_langsmith_evaluation_example.py)、[DeepEval入口](deepeval_wealth_advisor.py)
- 运行情况：未运行；已做静态检查。

## 代码怎么看

1. 主程序 `WealthAdvisorState`（103–121行）定义输入、过程状态与输出。
2. `assess_query`（244–283行）让模型选择 reactive / deliberative；`create_wealth_advisor_workflow`（461–509行）据此分支。
3. 简单路径为 assess → reactive → respond；复杂路径为 assess → collect_data → analyze → recommend → respond。
4. [规则评估脚本](2-langsmith_testing_evaluation.py)中的 `ProcessingModeEvaluator`（199–234行）比较模式；`ResponseCompletenessEvaluator`（236–275行）计算关键词覆盖率。
5. [DeepEval脚本](deepeval_wealth_advisor.py)的 `create_test_case`（108–118行）封装测试输入，`get_metrics`（123–157行）建立相关性、幻觉与风险偏好指标。

## 使用条件

当前仅做静态阅读，未安装依赖、未调用模型或评估平台。原始 requirements.txt 原样保留，不能据此认定环境已可运行。以下命令按源码入口整理，均待运行确认；先进入本案例目录，再执行命令，避免相对文件加载失败。

- 主程序：`python 1-hybrid_wealth_advisor_langgraph_langsmith.py`；需要 `DASHSCOPE_API_KEY`。
- LangSmith：`python 3-run_langsmith_evaluation_example.py`；需 `LANGSMITH_API_KEY`、`LANGCHAIN_TRACING_V2=true`，可设 `LANGCHAIN_PROJECT`。
- DeepEval：`python deepeval_wealth_advisor.py`；另需 DeepEval 包和 `OPENAI_API_KEY`，指标代码指定 `gpt-4o-mini`。原依赖清单未列 DeepEval，兼容版本待确认。
- `query_shanghai_index`（232–241行）返回固定行情，客户画像也来自内存样例，没有真实行情服务或真实客户数据接入。
- DeepEval 用例的上下文参数与当前指标版本是否匹配仍待核验，不应把存在指标定义当作评估已跑通。
