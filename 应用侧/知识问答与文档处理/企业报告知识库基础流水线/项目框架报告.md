# RAG-Challenge-2 项目框架报告

## 一、项目概述

本项目是 **RAG Challenge 2** 竞赛的获奖解决方案，专门用于处理企业年报问答系统。项目通过组合多种 RAG 技术，在公司年报问答任务中取得了最优结果。

### 核心特性
- **自定义 PDF 解析**：使用 Docling 提取结构化文档内容
- **混合检索**：向量检索 + BM25 + 父文档检索
- **LLM 重排序**：基于大模型的相关性评分
- **结构化输出**：CoT（Chain-of-Thought）推理提示
- **多模型支持**：OpenAI、阿里 DashScope、IBM Watsonx、Gemini

## 三、核心模块说明

### 3.1 管道编排层 (`pipeline.py`)

**职责**：流程配置与阶段编排

```python
PipelineConfig     # 路径配置
RunConfig          # 运行参数配置
Pipeline           # 主流程类
```

**关键流程阶段**：
1. `parse_pdf_reports()` - PDF解析
2. `serialize_tables()` - 表格序列化
3. `merge_reports()` - 报告规整
4. `chunk_reports()` - 文本分块
5. `create_vector_dbs()` / `create_bm25_db()` - 索引构建
6. `process_questions()` - 问答处理

**预置配置**（可复用）：
- `max_nst_o3m_config` - 最佳性能配置（推荐）
- `base_config` - 基础配置
- `parent_document_retrieval_config` - 父文档检索
- `gemini_thinking_config` - 全上下文模式

---

### 3.2 PDF解析层 (`pdf_parsing.py`)

**核心类**：
- `PDFParser` - PDF解析器（Docling封装）
- `JsonReportProcessor` - 报告组装器

**功能特性**：
- 多进程并行解析
- OCR识别（EasyOCR）
- 表格结构提取（TableFormer）
- 页码顺序归一化
- 调试数据保存

**输出格式**：
```json
{
  "metainfo": {"company_name", "sha1_name", "pages_amount", ...},
  "content": [{"page": 1, "content": [...]}],
  "tables": [{"table_id", "page", "markdown", "html", "json"}],
  "pictures": [...]
}
```

---

### 3.3 文本分块层 (`text_splitter.py`)

**核心类**：`TextSplitter`

**分块策略**：
- 基于 LangChain `RecursiveCharacterTextSplitter`
- 默认 chunk_size: 300 tokens
- chunk_overlap: 50 tokens
- 支持序列化表格插入
- Token 统计（tiktoken）

---

### 3.4 索引构建层 (`ingestion.py`)

**核心类**：

| 类名 | 功能 |
|------|------|
| `VectorDBIngestor` | 构建 FAISS 向量索引 |
| `BM25Ingestor` | 构建 BM25 倒排索引 |

**向量构建流程**：
1. 批量获取 embeddings（DashScope/OpenAI）
2. 转换为 numpy 数组
3. 使用 FAISS IndexFlatIP（内积相似度）
4. 保存 .faiss 文件

---

### 3.5 检索层 (`retrieval.py`)

**检索器类型**：

| 检索器 | 特点 | 适用场景 |
|--------|------|----------|
| `BM25Retriever` | 传统关键词检索 | 快速原型 |
| `VectorRetriever` | 语义向量检索 | 语义相似匹配 |
| `HybridRetriever` | 向量+LLM重排序 | 高精度问答 |

**关键特性**：
- 按公司名隔离检索
- 父文档检索模式（返回整页而非分块）
- 支持 DashScope/OpenAI 嵌入
- LLM 重排序融合（加权平均）

---

### 3.6 重排序层 (`reranking.py`)

**重排序器**：

| 类型 | 原理 | 优势 |
|------|------|------|
| `JinaReranker` | Jina API重排 | 多语言支持 |
| `LLMReranker` | LLM相关性评分 | 深度语义理解 |

**融合公式**：
```
combined_score = llm_weight × relevance_score + vector_weight × distance
```

---

### 3.7 问答处理层 (`questions_processing.py`)

**核心类**：`QuestionsProcessor`

**处理流程**：
1. 从问题中提取公司名
2. 判断是否为比较问题
3. 单公司问题 → 检索 → 生成答案
4. 多公司比较问题 → 拆分为单问题 → 并行处理 → 汇总比较

**答案类型**（schema）：
- `name` - 实体名称
- `number` - 数值型指标
- `boolean` - 是/否
- `names` - 多实体列表
- `comparative` - 比较结论

---

### 3.8 提示词系统 (`prompts.py`)

**核心提示词类**：

```python
# 问题重写（比较问题拆分）
RephrasedQuestionsPrompt

# RAG问答（含结构化输出）
AnswerWithRAGContextNamePrompt      # 名称类
AnswerWithRAGContextNumberPrompt   # 数值类
AnswerWithRAGContextBooleanPrompt  # 布尔类
AnswerWithRAGContextNamesPrompt    # 多名称类
AnswerWithRAGContextSharedPrompt   # 共享基础

# 比较答案
ComparativeAnswerPrompt

# JSON修复
AnswerSchemaFixPrompt

# 重排序
RerankingPrompt
```

**结构化输出 Schema**：
```python
AnswerSchema:
  - step_by_step_analysis: str    # 详细推理（≥5步，≥150字）
  - reasoning_summary: str         # 推理摘要（约50字）
  - relevant_pages: List[int]      # 引用页码
  - final_answer: Union[str, float, bool, List]  # 最终答案
```

### 3.9 API封装层 (`api_requests.py`)

**支持的提供商**：

| 提供商 | 处理器类 | 默认模型 |
|--------|----------|----------|
| OpenAI | `BaseOpenaiProcessor` | GPT-4o |
| DashScope | `BaseDashscopeProcessor` | Qwen-Turbo |
| IBM | `BaseIBMAPIProcessor` | Llama-3.3-70B |
| Gemini | `BaseGeminiProcessor` | Gemini-2.0-Flash |

**统一接口**：
```python
APIProcessor(provider="dashscope")
processor.send_message(...)        # 通用消息发送
processor.get_answer_from_rag_context(...)  # RAG问答
processor.get_rephrased_questions(...)     # 问题重写
```

---

### 3.10 表格序列化层 (`tables_serialization.py`)

**核心类**：`TableSerializer`

**功能**：
- 提取表格上下文（前后文本）
- LLM 序列化表格为独立信息块
- 并行/异步处理
- 上下文独立的信息块设计

**序列化 Schema**：
```python
TableBlocksCollection:
  - subject_core_entities_list: List[str]      # 核心实体
  - relevant_headers_list: List[str]           # 相关表头
  - information_blocks: List[                  # 独立信息块
    {
      "subject_core_entity": str,
      "information_block": str
    }
  ]
```

## 五、配置选项详解

### 5.1 RunConfig 关键参数

```python
@dataclass
class RunConfig:
    use_serialized_tables: bool = True      # 使用序列化表格
    parent_document_retrieval: bool = True   # 父文档检索
    use_vector_dbs: bool = True             # 向量检索
    use_bm25_db: bool = False               # BM25检索
    llm_reranking: bool = True              # LLM重排序
    llm_reranking_sample_size: int = 30     # 重排序采样数
    top_n_retrieval: int = 10               # Top-N检索数
    parallel_requests: int = 4              # 并发请求数
    api_provider: str = "dashscope"         # API提供商
    answering_model: str = "qwen-turbo-latest"  # 回答模型
```

## 六、部署与运行

### 6.1 环境准备

```bash
# 克隆项目
git clone <repo_url>
cd RAG-Challenge-2-main

# 创建虚拟环境
python -m venv venv
.\venv\Scripts\Activate.ps1

# 安装依赖
pip install -r requirements.txt
```

### 6.2 API密钥配置

```bash
# 创建 .env 文件
cp env .env

# 编辑 .env，添加密钥
OPENAI_API_KEY=sk-xxx
DASHSCOPE_API_KEY=sk-xxx
```

### 6.3 运行方式

**方式一：直接运行 pipeline.py**
```python
# 修改 src/pipeline.py 中的配置
pipeline = Pipeline(root_path, run_config=max_nst_o3m_config)
pipeline.parse_pdf_reports_sequential()
pipeline.serialize_tables(max_workers=5)
pipeline.merge_reports()
pipeline.chunk_reports()
pipeline.create_vector_dbs()
pipeline.process_questions()
```

**方式二：CLI 命令**
```bash
# 下载模型
python main.py download-models

# 解析PDF
python main.py parse-pdfs --parallel --chunk-size 2

# 序列化表格
python main.py serialize-tables --max-workers 10

# 处理报告
python main.py process-reports --config max_nst_o3m

# 处理问题
python main.py process-questions --config max_nst_o3m
```
