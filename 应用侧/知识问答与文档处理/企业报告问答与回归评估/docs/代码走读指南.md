## 1. 在线问答完整链路（本次跑通的流程）

### 步骤 0：初始化
- **位置**：`src/pipeline.py` → `Pipeline.__init__`
- **做什么**：`_initialize_paths()` 生成 `PipelineConfig`，算出所有输入输出路径；`_convert_json_to_csv_if_needed()` 检查 subset。
- **关键变量**：`self.paths`（路径集合）、`self.run_config`（= `configs['max_nst_o3m']`）。
- **本次生效的配置**：`parent_document_retrieval=True`、`llm_reranking=True`、`parallel_requests=4`、`api_provider='dashscope'`、`answering_model='qwen-turbo'`、`config_suffix='_max_nst_o3m'`。

### 步骤 1：问答入口
- **位置**：`Pipeline.process_questions()`（pipeline.py）
- **做什么**：把 RunConfig 开关翻译给 `QuestionsProcessor`，并用 `_get_next_available_filename()` 生成不重复输出名。
- **关键变量**：`output_path` = `answers_max_nst_o3m.json`（已存在则自动 `_01`、`_02`……）。

### 步骤 2-3：批量调度
- **位置**：`QuestionsProcessor.process_all_questions()` → `process_questions_list()`（questions_processing.py）
- **做什么**：加载 `questions.json` → 每题加 `_question_index` → 按 `parallel_requests=4` 分批 → 线程池执行。
- **关键变量**：`self.answer_details`（预分配列表，按索引存每题推理过程/错误）、`self.questions`。

### 步骤 4：单题包装
- **位置**：`_process_single_question()`
- **做什么**：取 `question_text` 与 `kind` → 调步骤 5 → 组装提交格式字典；任何异常进 `_handle_processing_error()`，不会中断批量流程。
- **输出字典字段**：`question_text / kind / value / references / answer_details($ref)`。

### 步骤 5：问题路由（公司识别）
- **位置**：`process_question()` → `_extract_companies_from_subset()`
- **做什么**：用 `subset.csv` 的公司名表对问题做不区分大小写的正则匹配（长名优先），得到 `extracted_companies`。
- **分支**：1 家公司 → 步骤 6；多家公司 → `process_comparative_question()`（LLM 拆子问题 → 并行各公司 → LLM 汇总）。

### 步骤 6：检索 + 生成答案（核心）
- **6.1 选检索器**（`get_answer_for_company()` 开头）：
  `llm_reranking=True` → `HybridRetriever`；`full_context=True` → `retrieve_all()`（本次未启用）。
- **6.2b 向量召回**（`VectorRetriever.retrieve_by_company_name()`，retrieval.py）：
  问题 → DashScope `text-embedding-v1` 取向量 → 在该公司报告的 FAISS（IndexFlatIP）中查 top 30
  → 因 `parent_document_retrieval=True`，把命中 chunk 换成**所属整页文本**并按页去重。
  关键变量：`self.all_dbs`（5 份报告的 文档+索引 对）、`distances/indices`（内积分数，越高越相似）。
  > 加载索引时经过 `_faiss_read_index()`：中文路径先复制到临时目录再读（Windows 兼容修复）。
- **6.2c LLM 重排**（`LLMReranker.rerank_documents()`，reranking.py）：
  30 个候选按 batch(=2) 送 qwen-turbo 打分 → `combined_score = 0.7×LLM分 + 0.3×向量分` → 降序。
  > dashscope 返回纯文本、LLM 分为占位 0.0，实际排序退化为向量分，依然有效。
- **6.3 拼上下文**（`_format_retrieval_results()`）：top 页拼成
  `Text retrieved from page N: """..."""` 的 RAG 上下文。
- **6.4 LLM 回答**（`APIProcessor.get_answer_from_rag_context()`，api_requests.py）：
  `kind='boolean'` → 选中 `AnswerWithRAGContextBooleanPrompt`（SO CoT：要求分步推理 + 引用页 + 最终答案）
  → `BaseDashscopeProcessor.send_message()` 调 qwen-turbo
  → 字段兜底（dashscope 无结构化输出，缺字段补空）。
- **步骤 7：引用校验**（`_validate_page_references()`）：剔除 LLM 幻觉出的、不在检索结果中的页码；
  不足 2 页用检索 top 页补齐；超 8 页截断 → `_extract_references()` 生成 `{pdf_sha1, page_index}`。
- **步骤 8：落盘**（`_save_progress()`）：每批写 `_debug.json`（完整推理/错误）；
  最后写提交文件，页码 1-based → 0-based，N/A 答案清空引用。

**本次实测产出**（`data/test_set/answers_max_nst_o3m_04.json`）：
问题关于 Mercia Asset Management PLC 是否提及并购 → 答案 `false`，引用第 18、41 页。

## 2. 离线建库链路（pipeline.py `__main__` 的 7 步）

| 步 | 方法 | 位置 | 输入 → 输出 |
|---|---|---|---|
| 1 | `parse_pdf_reports_sequential()` | pipeline.py → `PDFParser` (pdf_parsing.py) | `pdf_reports/*.pdf` → `debug_data/01_parsed_reports/*.json` |
| 2 | `serialize_tables()` | pipeline.py → `TableSerializer` (tables_serialization.py) | 给每个表格加 `serialized` 字段（LLM 拆成上下文独立信息块）|
| 3 | `merge_reports()` | pipeline.py → `PageTextPreparation` (parsed_reports_merging.py) | 解析 JSON → `02_merged_reports/*.json`（每页一段干净文本）|
| 4 | `export_reports_to_markdown()` | 同上 | 导出 `03_reports_markdown/*.md`（仅人工复核/全文模式用）|
| 5 | `chunk_reports()` | pipeline.py → `TextSplitter` (text_splitter.py) | 每页切 chunk(300tok/重叠50) → `databases/chunked_reports/*.json` |
| 6 | `create_vector_dbs()` | pipeline.py → `VectorDBIngestor` (ingestion.py) | chunk 批量 embedding → `databases/vector_dbs/*.faiss` |
| 7 | `process_questions()` | 即上一章步骤 1-8 | `questions.json` → `answers*.json` |

由于 ERC2 数据无法获取，本项目自建了一套虚构中文数据集，并已验证 **13/13 题全部正确**。

| 文件/目录 | 内容 |
|---|---|
| `subset.csv` | 4 家虚构公司：星辰科技（半导体）、蓝海能源（新能源）、峰瑞制药（医药）、恒宇银行（银行）|
| `questions.json` | 13 道题，覆盖全部 5 种类型（number×4 / boolean×3 / name×2 / names×1 / comparative×2），含 1 道"量子跳动"不在库中的 N/A 防幻觉测试题 |
| `debug_data/02_merged_reports/*.json` | 4 份虚构年报（每份 7 页，含财务摘要/高管/分红/风险等章节），与真实 pipeline 规整产物格式一致 |
| `databases/` | 由标准流程分块 + DashScope embedding 建好的向量库 |

生成与复现方式：`python scripts/build_my_set.py` 重新生成数据；随后用
`TextSplitter` + `VectorDBIngestor` 建库（详见脚本头部注释）；问答运行：
`cd data/my_set && python ../../main.py process-questions --config max_nst_o3m`。

### 3.4 为兼容中文数据集所做的路由改写

| 改写点 | 位置 | 原因 |
|---|---|---|
| 公司名匹配增加"纯包含"回退 | `questions_processing.py` `_extract_companies_from_subset()` | 原正则要求公司名后是标点/空白（`\W`），中文公司名后常直接跟"的"等字词导致永远匹配不到 |
| 比较题拆解结果兼容纯文本 | `api_requests.py` `get_rephrased_questions()` | dashscope 无结构化输出，返回的 JSON 字符串需 `json_repair` 修复后解析 |
| DashScope 答案自动解析 JSON | `api_requests.py` `BaseDashscopeProcessor.send_message()` | qwen 输出的 SO CoT JSON 字符串自动解析为 dict，`value` 字段不再嵌套原始文本 |

## 4. 路径含义速查（PipelineConfig 全量）

以 `root_path = data/test_set` 为例，`suffix` 在 `use_serialized_tables=True` 时为 `_ser_tab`（本次为空白）：

| 配置字段 | 实际路径 | 含义 |
|---|---|---|
| `subset_path` | `subset.csv` | 公司元数据（路由+引用）|
| `questions_file_path` | `questions.json` | 问题输入 |
| `pdf_reports_dir` | `pdf_reports/` | 原始 PDF（仅步骤 1 需要）|
| `answers_file_path` | `answers{suffix}.json` | 最终答案输出 |
| `debug_data_path` | `debug_data/` | 中间产物根目录 |
| `databases_path` | `databases[suffix]/` | 建库产物根目录 |
| `vector_db_dir` | `databases/vector_dbs/` | FAISS 索引（步骤 6.2b 读取）|
| `documents_dir` | `databases/chunked_reports/` | 分块文档（含整页文本，父文档检索的数据源）|
| `bm25_db_path` | `databases/bm25_dbs/` | BM25 索引（可选稀疏检索，本次未用）|
| `parsed_reports_path` | `debug_data/01_parsed_reports/` | Docling 解析输出 |
| `parsed_reports_debug_path` | `debug_data/01_parsed_reports_debug/` | Docling 原始导出（调试）|
| `merged_reports_path` | `debug_data/02_merged_reports[suffix]/` | 规整后每页文本 |
| `reports_markdown_path` | `debug_data/03_reports_markdown[suffix]/` | Markdown 导出 |
