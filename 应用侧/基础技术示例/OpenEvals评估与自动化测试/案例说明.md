# OpenEvals评估与自动化测试

从单项提示词评分，过渡到投顾应用的批量评估。

- 案例类型：基础技术示例（含投顾集成示例）
- 技术栈：Python、OpenEvals、ChatTongyi、LangSmith；被测应用使用 LangGraph
- 能力标签：LLM作为裁判、相关性、简洁性、RAG评估、自定义评分、批量实验
- 代码入口：[单项正确性](1-correctness.py)、[集成评估](12-openevals_evaluators.py)
- 运行情况：未运行；已做静态检查。

## 代码怎么看

1. `1-correctness.py` 44行起用 `create_llm_as_judge` 创建裁判，再传入问题、回答和参考输出。
2. 2–11号脚本依次覆盖简洁性、回答相关性、RAG帮助性、忠实度、检索相关性、有害性、幻觉、代码正确性、带参考的代码正确性、计划遵循度。
3. `12-openevals_evaluators.py` 的 `predict`（65–98行）调用投顾应用，给输出加上处理模式标记。
4. 同文件160–212行建立5个预定义评分器和2个自定义提示词评分器，230–292行定义6条用例，330–337行提交 LangSmith 评估。
5. 保留的 `2-langsmith_testing_evaluation.py` 用于对比规则评分实现；[投顾AI助手效果评估](../../金融投研与投顾/投顾AI助手效果评估/案例说明.md)解释同一被测应用。

## 使用条件

当前仅做静态阅读，未安装依赖、未调用模型或评估平台。原始 requirements.txt 原样保留，不能据此认定环境已可运行。以下命令按源码入口整理，均待运行确认；先进入本案例目录，再执行命令，避免相对文件加载失败。

- 单项示例：`python 1-correctness.py`，需要 `DASHSCOPE_API_KEY`；裁判为代码指定的 `qwen-turbo`。
- 集成示例：`python 12-openevals_evaluators.py`，另需 `LANGSMITH_API_KEY` 和可访问的 LangSmith 服务。
- 依赖文件未显式列出 DashScope SDK，实际安装完整性待确认。
- 集成脚本294–314行会删除并重建同名 `wealth-advisor-openevals-dataset` 数据集，运行前须使用专用测试项目并核对数据集；本轮没有执行。
- 代码正确性脚本使用模型评分，并非执行代码测试；RAG脚本使用手工字符串，不含真正的向量检索链路。
