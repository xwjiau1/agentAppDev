# 技术库维护规则

## 目录与导航

本仓库按“应用实现 → 框架技术 → Python 机制”积累知识，以 [内容索引](内容索引.md) 为完整目录，以 [首页](../README.md) 为业务用途与技术栈导航。

| 目录 | 维护内容 | 新增时需要同步 |
|---|---|---|
| `application/` | 按业务分类保存案例、完整源码和必要示例资源 | `案例说明.md`、首页应用表、相关技术解析 |
| `Python-appc/` | 按机制分类解释框架与工程实现 | 关联案例、源码链接、首页技术表 |
| `Python-base/` | 按语言机制分类保存知识点 | 基础速查 README、真实案例与源码引用 |
| `doc/` | 使用指南、专题路线、维护和验证记录 | 内容索引与必要的首页入口 |
| `scripts/` | 无外部依赖的仓库维护工具 | 本规则中的使用命令与验证范围 |

现有目录迁移映射为：`应用侧/` → `application/`，`框架技术侧/` → `Python-appc/`，`Python基础侧/` → `Python-base/`，`文档/` → `doc/`。后续使用新路径，调整分类时同时迁移引用。

## 内容要求

1. 先检索已有案例和主题。相同实现复用说明；不同框架或编排方式分别解释，明确差异。
2. 案例说明至少包含用途、来源与许可、技术栈、入口、处理流程、依赖与配置、数据条件、关联技术文档及验证状态。
3. 技术解析包含实现机制、应用思路、实际源码与解释、差异和边界。源码链接尽量附准确行号；节选不是独立可运行程序。
4. Python 知识点沿用“速记 → 面试问答 → 实际案例与代码 → 易错追问”，并维护复习优先级。
5. 保留第三方项目内部结构、许可证与作者信息。源码有问题时记录具体问题，修复时另说明依据与验证结果。
6. 使用 UTF-8 和仓库相对链接；文件名描述明确，空格在链接中编码。不要写本机绝对路径。
7. 新增配置使用示例和占位符。凭据、环境、模型权重、下载缓存及临时输出不入库；现有示例资源的清理另做专项变更。

## 更新与验证

在仓库根目录执行，Python 3.10 及以上，无需安装第三方包：

```powershell
python scripts/maintain.py index
python scripts/maintain.py check
git diff --check
```

`index` 扫描两级案例目录的 `案例说明.md`、两级技术解析和 Python 知识点，按分类生成完整索引。源码、依赖文件、第三方内部文档及资源文件不逐个列入索引。新增层级或改变归档模式时同步修改脚本。

`check` 校验索引是否最新、维护文档中的 Markdown 本地文件链接是否存在、源码 `#L起始-L结束` 行号是否越界。它不访问外部网站，不验证标题锚点、第三方内部文档、源码节选一致性或应用运行效果。引用式链接及复杂嵌套链接需要人工核对。

修改源码时，另核对引用行号和节选，并执行适合该案例的局部检查；不要把整库样例当成可统一执行的测试集。已知历史问题保留在 [归档与验证记录](归档与验证记录.md)，每次新增验证注明范围、命令、结果和未验证项。旧记录中的数量只代表对应批次。

## 本地与远程双端同步

远程为 [xwjiau1/agentAppDev](https://github.com/xwjiau1/agentAppDev)，当前主分支为 `main`。双端同步以 Git 提交为单位，不复制 `.git`、虚拟环境或本机配置。

开始维护时先检查：

```powershell
git status --short --branch
git remote -v
git ls-remote --symref origin HEAD
git fetch origin
git rev-list --left-right --count HEAD...origin/main
```

最后一条依次显示本地独有、远程独有提交数。只有工作区干净、位于对应分支且可以快进时才执行 `git pull --ff-only origin main`。存在未提交改动先明确归属；存在分叉时先分析双方变更，再合并或按协作约定 rebase，不直接覆盖任何一端。

本次用户已确认将既有目录改名、链接修复、索引及维护规则一并提交并推送。以后仍需按当次任务范围选择暂存文件，不无条件使用 `git add .`。检查暂存差异、通过验证后提交；在 `main` 上执行的同步命令为：

```powershell
git diff --cached --stat
git diff --cached --check
git commit -m "docs: update agent knowledge catalog and maintenance rules"
git push origin main
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
git ls-remote origin refs/heads/main
git rev-list --left-right --count HEAD...origin/main
git status --short --branch
```

功能改动按需使用 `codex/<主题>` 分支，并将上述核对对象改为实际跟踪分支。同步成功要求 push 成功、本地和远程哈希一致、ahead/behind 为 `0 0`，且工作区没有遗漏的任务变更。仅 ls-remote 成功说明远程可读；push 被拒绝时记录原因，解决认证、权限或远程新增提交后重试。禁止强推和破坏性重置。
