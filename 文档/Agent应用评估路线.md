# Agent应用评估路线

先确定业务行为，再选择评分方式，最后通过追踪定位失败原因。

1. [工具循环与混合式投顾](../应用侧/金融投研与投顾/工具循环与混合式投顾/案例说明.md)展示工具循环；[投顾效果评估](../应用侧/金融投研与投顾/投顾AI助手效果评估/案例说明.md)保留另一份被测实现。两者源码有差异，不能将一份的测试结果直接算作另一份的结果。
2. [LangSmith效果评估](../框架技术侧/效果评估/LangSmith效果评估.md)以规则比较模式和关键词；[OpenEvals效果评估](../框架技术侧/效果评估/OpenEvals效果评估.md)对语义维度及自定义提示词评分。
3. [DeepEval效果评估](../框架技术侧/效果评估/DeepEval效果评估.md)将实际回答封装为测试对象，再应用内置与自定义指标。裁判所需上下文应逐项核对。
4. [LangSmith调用追踪](../框架技术侧/调用追踪/LangSmith调用追踪.md)与[Langfuse调用追踪](../框架技术侧/调用追踪/Langfuse调用追踪.md)记录执行证据；追踪成功不等于业务评分通过。

固定规则可以确定性判断时，优先理解规则评分。模型评分需要独立核对参考数据和评分方向。现有样例未完成外部服务运行核验，不提供实测准确率或部署效果承诺。
