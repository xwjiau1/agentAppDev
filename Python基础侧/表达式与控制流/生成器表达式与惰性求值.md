# 生成器表达式与惰性求值

> 复习优先级：必背。先记结论，再用案例解释“这行代码做了什么、有哪些边界”。

## 面试速记

`(表达式 for ... if ...)`产生生成器，迭代时才逐项求值。sum、any、all等可直接消费它，避免额外创建结果列表。

## 面试问答

**问：生成器表达式能重复遍历吗？** 同一生成器消耗后不会自动重置。

**问：`any`与`all`会完整遍历吗？** any遇到真值、all遇到假值时即可短路停止。

## 实际案例与代码

[LangChain文本工具与LCEL组合](../../应用侧/基础技术示例/LangChain文本工具与LCEL组合/案例说明.md) · [2-simple_toolchain.py，24–26行](../../应用侧/基础技术示例/LangChain文本工具与LCEL组合/2-simple_toolchain.py#L24-L26)

以下为当前仓库原代码，统一去除外层缩进；它是源码节选，不是独立运行程序。

```python
positive_count = sum(1 for word in positive_words if word in text)
negative_count = sum(1 for word in negative_words if word in text)
sentiment = "积极" if positive_count > negative_count else "消极" if negative_count > positive_count else "中性"
```

每命中一个正面词生成数字1，sum逐项相加。这里统计命中的词表项数量，不是每个词在文本中的出现次数。

## 易错点与追问

惰性不等于零内存；输入与闭包持有对象仍占内存。生成器中的异常常在迭代时才暴露。
