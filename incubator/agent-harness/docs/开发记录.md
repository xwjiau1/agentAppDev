## 2026-11-24：D0 设计与孵化目录

**交付**：创建项目目录、README、MVP 设计、开发计划、开发记录，以及一个文件提取任务的输入、任务说明和预期 JSON。将孵化项目接入仓库导航、内容索引与文档链接检查。

**主要决策**：

| 决策 | 目的 |
|---|---|
| Python CLI，单进程单 Agent，工具串行 | 保持控制流直白 |
| 只有 read_file / write_file | 从完整文件任务验证循环 |
| 先模拟模型，后一个真实模型 | 开发和边界测试不依赖密钥 |
| 预算只承诺模型调用、工具调用和工作时长 | 先提供可准确检查的停止边界 |
| 单写入者 JSONL，暂缓 SQLite 和恢复 | 首版只需过程查看和正常取消收尾 |
| 确定性 JSON 验收，运行状态和验收结果分开 | 避免模型说完成就当通过 |
| 原调研仍作长期路线，本项目文档约束 v0.1 | 明确缩小范围，减少开发负担 |

**验证结果**：

- `python scripts/maintain.py index`：索引已更新，孵化项目独立计数。
- `python scripts/maintain.py check`：167 篇维护文档、993 处本地文件链接，错误 0 项。
- `git diff --check`：通过。
- 示例 JSON 可解析，三个字符串字段与输入文件完全一致；维护脚本语法、孵化项目发现、四篇项目文档检查覆盖和索引一致性验证通过。
- `git check-ignore`：本项目 `.runs/` 运行产物与 `.env` 被忽略。

以上是文档与维护工具验证，不代表 MVP 已实现或可运行。

## 2026-11-24：技术实现方案与工程质量基线

**交付**：新增技术实现方案，逐项说明场景、约束、技术选择、维护成本和替换条件；同步 README、MVP 设计与开发计划。

**决策**：最低 Python 3.12，首版验收 3.12；asyncio、标准库 CLI、dataclass/Protocol 与 JSONL；真实模型使用可选 HTTPX。uv 管环境和锁文件，uv_build 打包；Ruff、mypy、unittest 与 coverage.py 构成质量检查，计划在 Windows/Linux 运行离线 CI。

**理由与边界**：Python 3.12 简化 Windows junction 检查；模拟与真实模型共用一个接口；六个业务模块增加一个共享契约文件，避免循环导入。存储仍只有一个具体实现，暂不建立多层框架。进一步明确实际请求体快照、协作式取消、不完整轨迹检查以及自动测试与真实控制台验证的区别。

**依据**：核对 Python、HTTPX、uv、Ruff、Pyright、mypy、unittest 与 coverage 官方资料，来源链接随技术方案保存。类型检查原考虑 Pyright，发现 CLI 需要 Node 后，针对当前场景改选 mypy。本机 Python 为 3.12.8，未发现 uv/Ruff/mypy 命令；本次未安装依赖、未创建锁文件、未运行尚不存在的质量工具或 Agent。

**验证**：`python scripts/maintain.py index`、`python scripts/maintain.py check` 和 `git diff --check` 通过；168 篇维护文档、1001 处本地链接，错误 0 项。项目五篇文档的 UTF-8、模型接口示意语法、Python 版本及类型检查器选型一致性已核对。运行时、工具链与 CI 均待 D1–D4 实施验证。

**下一步**：仍从 D1 开始，先建立独立可复现环境、数据契约和正常离线链路，不扩大 MVP 功能范围。
